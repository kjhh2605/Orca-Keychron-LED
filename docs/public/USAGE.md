# 사용 사례와 문제 해결

**설치할 때는 USB, 평소 연동은 Bluetooth입니다.** 이미 설정 지원 펌웨어가 설치된 키보드라면 색상·효과를 바꿀 때마다 다시 설치할 필요가 없습니다.

[README](../../README.md) · [설치·업데이트·복구](INSTALL.md) · [상태 판단과 검증 범위](STATUS.md)

![설치와 일상 사용의 연결 방식](connection-modes.svg)

## 매일 켜기

1. 키보드 스위치를 **BT**로 바꾸고 Mac에 연결합니다. USB 케이블은 없어도 되고 충전용으로 연결해도 됩니다.
2. `Orca LED.app`을 엽니다. Orca가 꺼져 있으면 연동 모드로 열고, Orca가 준비되면 LED 연동을 자동으로 시작합니다.
3. 조명 동기화를 기다린 뒤 F키로 작업공간을 엽니다. 첫 상태 전송은 약 7초, 전체 테마 전송은 약 2분이 걸릴 수 있습니다.

Orca가 평소 아이콘으로 켜져 있어 연동 모드가 아니면 **"Orca를 연동 모드로 다시 열까요?"** 확인창이 뜹니다. **다시 열기**를 누르면 Cmd+Q와 같은 방식으로 Orca를 종료하고 연동 모드로 다시 엽니다. 강제 종료하지 않으며, 저장하지 않은 작업이 있으면 먼저 정리하세요. **취소**하면 아무것도 바꾸지 않습니다. 메뉴 앱이 켜진 상태에서 `Orca LED.app`을 다시 열거나 메뉴의 **펌웨어 검증 후 시작**을 눌러도 같은 순서로 동작합니다. 앱 없이 Orca만 연동 모드로 열 때는 `scripts/start-orca-debug.command`를 사용할 수 있습니다.

현재 일상 브리지는 **Bluetooth 전용**입니다. 케이블이 연결되어 있어도 스위치를 Cable로 바꾸면 Bluetooth 일상 연동은 사용할 수 없습니다. USB는 백업·설치·지원 확인·시험용입니다.

## 색상과 효과 바꾸기

`Orca LED Settings.app`을 열고 상태를 고른 뒤 색상·효과·밝기·주기를 바꾸고 **저장 및 적용**을 누릅니다. 화면 미리보기는 바로 변하지만, 키보드는 무선 전송이 끝난 뒤 바뀝니다. 저장한 설정을 적용하는 데 펌웨어 재설치나 USB 케이블은 필요하지 않습니다.

![상태별 색상과 효과 설정 화면](settings-preview.png)

*예시 미리보기 화면이며 개인 작업 정보는 포함하지 않습니다.*

| 조작 | 결과 |
|---|---|
| 색상·효과 편집 | 화면 미리보기만 바뀜 |
| 저장 및 적용 | Mac에 저장하고, 연동 중이면 키보드 전송을 요청 |
| 변경 취소 | 마지막으로 저장한 값으로 편집 화면 복귀 |
| 기본값 복원 | 기본값을 편집 화면에 불러옴; 실제 적용하려면 저장 필요 |
| 같은 값을 다시 저장 | 전체 테마 재전송 요청 |
| 전체 밝기 조정 | 모든 상태에 적용; 저장 필요 |

이후 변경분은 바뀐 상태만 전송합니다. 전체 테마가 이미 전송된 뒤 한 상태의 색상·효과를 바꾸는 작업도 수 초 이상 걸릴 수 있습니다. 기본 상태 한 칸의 약 3초 갱신과 테마 전송 시간을 혼동하지 마세요. Bluetooth에는 키보드의 수신 확인 응답이 없으므로 **전송 완료는 Mac의 전송 완료**입니다. 실제 LED도 함께 확인하세요.

미할당 키는 항상 꺼져 있고, 밝기가 0이거나 효과가 끄기인 상태는 연결이 정상이더라도 보이지 않습니다. 화면과 키보드 LED의 색감은 다를 수 있습니다.

## 어떤 앱을 닫으면 어떻게 되나요?

| 동작 | LED 연동 | Orca 작업 |
|---|---|---|
| 설정 앱 창 닫기·설정 앱 종료 | 계속 실행; 저장된 설정 유지 | 영향 없음 |
| LED 메뉴의 연동 중지 | 해제 명령 전송, 일반 F키·기존 조명으로 복귀 | 계속 실행 |
| LED 메뉴의 Orca LED 종료 | 연동 중지 후 메뉴 앱 종료 | 계속 실행 |
| Orca 창 최소화 | 연동 유지 | 계속 실행 |
| Orca 앱 종료 | 상태를 읽을 수 없어 연동 정보가 만료됨 | 앱 종료에 따른 영향이 있으므로 먼저 작업 저장 |
| 강제 종료·연결 끊김 | 마지막 유효 명령 후 약 15초에 F키 기능, 약 30초에 기존 조명 복귀 | 해당 앱과 연결 상태에 따름 |

설정 앱만 열어서는 연동이 시작되지 않습니다. `Orca LED.app`이 실행되어 있고 메뉴에서 연동을 시작해야 합니다. 반대로 설정 앱은 매일 계속 열어둘 필요가 없습니다. 저장하지 않은 설정 편집은 실제 키보드에 적용되지 않습니다.

## 재시작과 재연결

| 상황 | 순서 |
|---|---|
| 키보드 전원을 껐다 켰음 | BT 연결 확인 → 테마 재전송 대기 → 원래 색이면 LED 연동 중지·시작 또는 같은 설정 재저장 |
| Mac을 재시작했음 | Orca를 실행 스크립트로 열기 → LED 앱 열기 → 연동 시작 |
| Orca만 재시작했음 | `Orca LED.app`을 다시 열기. 일반 모드로 켜졌다면 확인창에서 **다시 열기** |
| Cable에서 BT로 돌아옴 | Mac의 BT 연결 확인 → LED 연동 시작 → 상태·테마 전송 대기 |
| 잠자기에서 깨어났는데 조명이 그대로임 | BT 연결과 Orca 상태 확인 → 연동 중지·시작 → 필요하면 같은 설정 재저장 |

키보드의 테마는 RAM에 저장하므로 전원을 끄면 사라집니다. Mac의 설정 파일은 남아 있어 연동 프로그램이 다시 보낼 수 있습니다. 자동 재연결·절전의 모든 경우를 실기로 검증한 것은 아니므로 정상 반영되지 않으면 위 순서로 다시 동기화하세요. 이 프로젝트는 Mac 로그인 시 자동 실행을 등록하지 않습니다.

## 펌웨어를 다시 설치해야 하는 경우

색상·효과·밝기·주기 변경에는 필요하지 않습니다. **새 펌웨어 기능 추가, 펌웨어 수정 버전 적용, 원래 펌웨어 복원**에는 USB 설치가 필요합니다. 앱이나 README만 바뀌었다면 그 사실만으로 키보드 펌웨어를 다시 설치하지 않습니다. 해당 변경의 호환성 안내를 확인하세요.

![커스텀 펌웨어 첫 설치·업데이트 흐름](firmware-flow.svg)

설치 전에 Cable 모드에서 현재 설정을 백업하고, 올바른 이미지·기기를 확인한 다음 물리 Reset으로 DFU에 진입합니다. **쓰기·읽기 검증·일반 USB 복귀가 끝날 때까지 데이터 케이블을 유지합니다.** **커스텀 펌웨어 설치·업데이트**는 이후 USB 테마 지원 확인을 거쳐 BT 연동을 시작합니다. 위 그림은 이 경우의 흐름입니다. **원본 복원**은 일반 키와 설정 확인 후 일반 키보드로 사용하는 것으로 마무리하며, 커스텀 테마 확인이나 Orca LED 연동을 시작하지 않습니다. 상세 절차와 원본 복구 조건은 [설치 문서](INSTALL.md)에 있습니다.

## USB 키보드가 보이지 않아요

1. 케이블이 **데이터 전송을 지원**하는지 확인합니다. 충전 LED만 켜지는 것은 USB 데이터 연결 증거가 아닙니다.
2. 일반 백업·지원 확인 단계라면 스위치가 **Cable**인지 확인합니다. BT 모드에서는 케이블을 연결해도 USB 대상 키보드로 찾지 못할 수 있습니다.
3. **펌웨어 쓰기 중이 아닐 때만** 케이블을 다시 연결하거나 다른 데이터 케이블·Mac 포트로 확인합니다. 처음 정상 연결에 사용한 케이블과 포트가 있다면 우선 사용합니다.
4. DFU 단계라면 일반 키보드가 아니라 업데이트 장치로 보이는 것이 정상입니다. 설치 도구가 올바른 DFU 장치를 확인했는지 봅니다. DFU 인식이 안 되면 모델별 물리 Reset 절차를 다시 확인합니다.

인식 문제를 해결하기 위해 공장 초기화·VIA 초기화·강제 펌웨어 쓰기를 먼저 하지 않습니다.

## 핑크·보라색이 계속 깜빡여요

기본 테마의 핑크·보라 점멸은 **확인 불가**입니다. Orca 연결이 정상이어도 에이전트 상태가 관측되지 않거나 인정하는 종료 신호가 없으면 표시됩니다. Codex는 Orca가 실제 `Stop`을, omp는 실제 `agent_end`(응답 턴 종료)를 관측하면 완료로 표시하지만, 터미널이 멈췄거나 작업이 끝나 보인다는 이유만으로 완료 상태를 추정하지 않습니다. Codex와 마찬가지로 omp의 완료도 결과의 정확성을 보장하지 않습니다.

omp는 Orca가 omp 훅에서 직접 관측했다는 출처 기록이 있는 상태만 사용합니다. 출처 기록이 없는 omp 터미널(터미널 제목으로 만든 상태, 복원 후 미확인 상태 등)과, 진행 중·대기인데 마지막 훅 관측 후 30분이 지난 터미널은 확인 불가로 표시합니다. 하나의 도구 실행이 30분 넘게 걸려도 그 사이 새 훅이 없으면 확인 불가가 될 수 있으며, 다음 훅이 오면 바로 원래 상태로 돌아옵니다. Orca를 다시 시작하기 전에 끝난 omp 턴은 출처 기록이 남지 않아, 그 세션의 다음 턴이 끝날 때까지 확인 불가로 보입니다.

한 작업공간에 상태 신호가 없는 터미널(에이전트를 종료한 탭, 일반 셸 등)이 하나라도 있으면, 다른 에이전트가 끝났어도 작업공간 전체를 완료 대신 확인 불가로 표시합니다. 일부만 끝난 작업공간을 초록색으로 보이지 않게 하려는 규칙입니다. 진행 중·대기·오류는 그대로 우선 표시됩니다. 쓰지 않는 탭을 닫으면 완료가 표시됩니다.

메뉴나 설정 화면에서 연결 오류도 함께 표시된다면 연결부터 점검하세요. 핑크색이라는 이유만으로 펌웨어를 다시 설치할 필요는 없습니다. 색상을 사용자가 바꿨다면 색 이름 대신 설정 앱의 상태 이름을 기준으로 확인합니다. [상태 판단 문서](STATUS.md)에 상세 기준이 있습니다.

## Codex 응답이 끝났는데 핑크색이거나 다른 칸이 바뀌어요

먼저 **완료의 의미**를 구분합니다. 이 연동에서 초록색은 명시적인 정상 완료 결과 또는 Orca가 실제 관측한 Codex `Stop`에 의한 **응답 턴 종료**입니다. 결과의 정확성, 테스트 통과, 사용자 요청 전체의 해결을 보장하지 않습니다. 명시적 실패는 오류, 취소·중단은 대기로 처리하며, 하위 작업이 아직 실행 중이면 계속 실행 상태를 반영합니다. 종료 신호 자체가 없으면 핑크색을 초록색으로 추정해서 바꾸지 않습니다.

최근 Codex CLI의 공유 백그라운드 서버는 훅을 원래 터미널이 아닌 서버 환경에서 실행할 수 있습니다. 이 때문에 터미널별 상태 알림을 연결하기 어렵다는 [upstream 이슈 #44902](https://github.com/openai/codex/issues/44902)가 있습니다. Orca에서 상태 신호가 누락되거나 다른 칸에 연결되는 현상도 이 환경 전달 문제와 관련될 수 있습니다. 이 이슈만으로 모든 상태 누락의 원인이 확정되는 것은 아닙니다.

**새 세션을 시작할 때** Orca의 해당 작업공간에 새 터미널을 열고 다음 명령을 사용합니다.

```sh
codex --no-daemon
```

로컬 Codex CLI **0.160.0**의 `codex --help`와 `codex resume --help`에서 `--no-daemon` 지원을 확인했습니다. 이 옵션은 이미 실행 중인 공유 서버가 있어도 그 서버를 사용하지 않고 시작합니다. 실행 중인 기존 Codex 세션을 자동으로 전환하지는 않습니다. 다른 버전에서 옵션을 인식하지 못하면 해당 버전의 도움말을 확인하세요.

기존 대화를 이어가야 한다면 **원래 세션을 정상 종료했고, 다른 클라이언트가 그 세션을 사용하거나 잠그고 있지 않음을 확인한 경우에만** 새 터미널에서 재개 선택기를 사용합니다.

```sh
codex resume --no-daemon
```

선택기에서 원하는 기존 대화를 고릅니다. 사용 중·잠금 오류가 나면 동시에 재개하거나 잠금 파일을 지우지 말고, 기존 세션이 어디서 실행 중인지 먼저 확인합니다. 이 문제를 해결하려고 실행 중인 에이전트나 공유 서버를 강제 종료할 필요는 없습니다.

새 세션에서 응답을 주고받은 뒤 Orca 상태와 조명이 실제로 바뀌는지 확인합니다. Codex 0.160.0 기존 대화를 `--no-daemon`으로 재개한 실기에서 F11의 **완료 → 진행 중 → 완료** 판정을 확인했고, 자동 테스트 145개가 통과했습니다. 수정본 재시작 후 물리 LED 확인은 대기 중이며, 이미 물리 검증된 펌웨어·테마 표시와 구분합니다. 키보드 재설치나 색상 재저장은 누락된 Codex 훅을 만들어 내지 않습니다.

## 설정은 저장됐는데 키보드는 그대로예요

다음 순서로 확인합니다.

1. 설정 앱만 실행한 상태가 아닌지 보고 **LED 메뉴에서 연동 시작**을 선택합니다.
2. 키보드가 **BT**로 Mac에 연결되어 있는지 확인합니다. Cable 모드는 일상 연동 대상이 아닙니다.
3. Orca가 연동 모드로 실행 중인지, 앱에 연결 오류가 없는지 확인합니다. **미검증** 버전은 조명은 표시하지만 F키 이동은 꺼져 있습니다([버전 검증](INSTALL.md#orca-업데이트-후-버전-검증)).
4. **펌웨어 업데이트 필요**라면 [USB 테마 지원 확인](INSTALL.md#5-색상과-효과)을 진행합니다. 이미 새 펌웨어가 있어도 확인 파일이 없으면 지원 확인부터 필요할 수 있습니다.
5. 전송 중이면 기다립니다. 전체 설정은 약 2분을 예상하고, 전체·상태별 밝기와 끄기 효과도 확인합니다.
6. 전송 완료 뒤에도 반영되지 않으면 같은 설정을 다시 저장해 전체 테마 재전송을 요청합니다. 계속 실패하면 LED 연동을 중지·시작하고 다시 확인합니다.

기존 테마를 잃지 않도록 설정 파일을 삭제하거나 앱을 반복 재설치하는 방법부터 시도하지 않습니다. 저장 실패로 표시된다면 프로젝트 폴더의 읽기·쓰기 권한과 macOS의 바탕화면 접근 허용을 확인하세요.

## Command·Option이나 다른 일반 키가 이상해요

먼저 메뉴에서 **연동 중지**를 선택하고 일반 키가 돌아오는지 확인합니다. 펌웨어를 재설치하거나 공장 초기화부터 하지 않습니다. 연동을 꺼도 이상하다면 키맵과 펌웨어의 사용자 정의 키 코드 의미가 맞는지 확인해야 합니다.

이 펌웨어는 Keychron 공식 펌웨어와 같은 키코드 순서를 사용하므로, VIA에서 공식 `firmware/recovery/k10_pro_us_rgb_v1.0.json`을 불러와 키를 확인·지정합니다. [키 코드 호환성 안내](INSTALL.md#mac-키-코드-호환성)를 참고하세요.

## 백업이 "Unreviewed VIA protocol 10"으로 멈춰요

키보드에 VIA 10을 쓰는 오래된 공식 펌웨어가 설치되어 있다는 뜻입니다. 백업·설치 도구는 VIA 12만 지원하므로 검사를 우회하지 말고, [Keychron Launcher](https://launcher.keychron.com)에서 **공식 펌웨어를 최신 버전으로 업데이트**한 뒤 백업을 다시 실행합니다. 자세한 순서는 [설치 문서](INSTALL.md#via-프로토콜이-12가-아니면-keychron-launcher로-공식-펌웨어-최신화)에 있습니다.

## 설치 후 키맵이나 조명이 바뀌었어요

펌웨어를 설치하면 VIA 키맵·매크로·레이아웃 옵션과 조명 효과·색상이 기본값으로 초기화됩니다. 펌웨어를 다시 설치하지 말고, 설치 전 백업과 비교한 뒤 VIA에서 공식 `firmware/recovery/k10_pro_us_rgb_v1.0.json`을 불러와 필요한 키를 다시 지정합니다. Orca LED 상태 조명은 설정 앱의 테마로 따로 전송되므로 VIA 조명 설정과 별개입니다.

## 문제가 생기면 원복할 수 있나요?

**자기 기기에서 두 번 읽어 일치를 검증한 원본**과 정확히 같은 대상 기기인지 확인할 근거가 있고, 물리 Reset으로 DFU가 동작한다면 해당 복구 절차로 원본 복원을 검토할 수 있습니다. 모든 고장 상태에서 복구가 보장되는 것은 아닙니다.

원본 복원이 끝나면 일반 키보드로 사용하세요. 일반 키보드의 Cable·BT 연결은 사용할 수 있지만, **Orca LED 테마 전송과 F키 연동은 중지 상태로 둡니다.** 커스텀 테마 지원 확인과 BT 연동 시작은 원본 복원 뒤의 절차가 아닙니다.

공장 초기화·VIA 초기화·설정 앱의 기본값 복원은 원본 펌웨어 복원과 다릅니다. 백업 키맵 JSON만으로 펌웨어 프로그램 전체를 복구할 수도 없습니다. 원본 이미지·읽기 검증 기록·설치 기록은 프로젝트 정리나 공개본 생성 때에도 보존하세요.

부팅이 안 되면 USB 전원·데이터 케이블·포트·물리 DFU 인식부터 확인합니다. DFU가 안 보이거나 검증한 원본이 없으면 강제 지우기·검증 우회를 시도하지 말고 Keychron 지원 또는 하드웨어 점검으로 이어가세요. [복원 조건](INSTALL.md#6-원래-펌웨어로-복원)에 더 자세히 정리했습니다.
