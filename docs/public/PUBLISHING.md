# GitHub 공개본 만들기

작동 중인 프로젝트에는 개인 복구 자료와 큰 빌드 캐시가 함께 있을 수 있습니다. 공개할 때는 작업 폴더를 통째로 복사하지 않고 명시적으로 허용한 소스만 새 폴더로 내보냅니다.

```sh
python3 scripts/export-public.py --output ../orca-keychron-led-github
```

내보내기는 원래 프로젝트를 수정하거나 백업을 삭제하지 않습니다. Git 저장소 생성·커밋·업로드도 수행하지 않습니다. 대상 폴더에 다른 파일이 있으면 덮어쓰지 않습니다. 같은 도구로 만든 공개본을 갱신하려면 `--replace`를 사용하며, 이전 공개본에 직접 고친 파일이나 추가한 파일이 있으면 중단합니다.

## 포함하는 파일

- 공개 README, 라이선스와 출처, `docs/public/`, 프로토콜 문서
- 설정 앱 자체에서 생성한 예시 화면 PNG 한 장(텍스트·EXIF 메타데이터 제외)
- 연결 모드와 펌웨어 작업 순서를 설명하는 SVG 그림 두 장(외부 참조·스크립트 없음)
- Python·Swift·C 소스, 앱 정보, 빌드·백업·복원 스크립트
- 고정된 펌웨어 소스·도구 목록과 패치
- 공개용 VIA 정의와 출처 기록
- 개인 자료에 의존하지 않는 자동 검사와 합성 예제
- 파일별 SHA-256을 기록한 `PUBLIC_EXPORT.json`

## 제외하는 파일

- 키맵·매크로·원본 전체 플래시를 포함한 **모든 개인 기기 백업**
- 장치 번호, USB 연결 경로, 복구 영수증, 설치 계획과 개인 검증 기록
- Orca 작업 이름·경로·ID가 들어갈 수 있는 런타임 상태와 로그
- `.app`, 펌웨어 `.bin`, `.elf`, `.map`, 컴파일 중간 파일
- 다운로드한 외부 소스·가상 환경·컴파일러·DFU 도구 캐시
- 비공개 원본 요구사항과 개인 사용 안내

`.gitignore`는 실수로 생성물을 추가하지 않도록 돕지만, 허용 목록 기반 내보내기의 대체가 아닙니다. 공개본은 텍스트와 경로를 검사해 사용자 홈의 절대 경로·개인 백업 참조·의심스러운 장치 식별 정보가 발견되면 중단합니다. 이 검사는 모든 비밀을 알아낼 수 있는 보장이 아니므로 최종 변경 내용을 검토하세요.

저장소에는 소스만 올립니다. 펌웨어 바이너리를 릴리스한다면 해당 파일과 정확히 대응하는 소스·패치·빌드 정보 및 각 구성요소의 라이선스를 함께 준비해야 합니다.

## 앱 릴리스

내려받아 바로 쓰는 앱은 GitHub Releases에 zip으로 올립니다.

```sh
./scripts/build-release.sh
```

`dist/Orca LED.app`과 `dist/Orca-LED-<버전>-macos-<아키텍처>.zip`을 만들고 zip의 SHA-256을 출력합니다. 앱 안에는 Python 연동 코드(`Contents/Resources/orca_led`), 설정 앱(`Contents/Helpers`), `LICENSE`와 `THIRD_PARTY_NOTICES.md`가 들어갑니다. 버전은 `native/Info.plist`의 `CFBundleShortVersionString`을 따릅니다.

1. 공개 저장소에 올린 커밋과 같은 소스에서 빌드합니다.
2. 같은 버전으로 태그를 만듭니다(예: `v0.2.0`).
3. 릴리스에 zip을 첨부하고 출력된 SHA-256을 릴리스 설명에 적습니다.

앱은 ad-hoc 서명만 되어 있고 Apple 공증을 받지 않았습니다. 사용자는 처음 실행할 때 **그래도 열기**가 필요합니다. 공증하려면 Apple Developer ID 인증서로 다시 서명하고 `notarytool`로 제출해야 합니다. 다른 사람의 실제 원본 펌웨어 백업을 일반 복원 파일로 배포하지 않습니다.
